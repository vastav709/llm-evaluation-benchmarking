# LLM Evaluation & Benchmarking Framework

A beginner-friendly Python project for evaluating and comparing text-model responses against reference answers.

## What this project demonstrates

- Dataset loading and validation with Pandas
- Exact-match scoring
- Token-level precision, recall and F1
- TF-IDF cosine similarity as a lexical similarity baseline
- Optional human quality ratings
- Model-level aggregation and comparison
- Error inspection and CSV report generation
- Reproducible evaluation from a fixed input dataset

> **Important:** The included `demo_responses.csv` contains illustrative, manually written example responses. They are not outputs generated by live LLMs. Do not describe the demo results as a real-world benchmark or as a comparison of actual deployed models. Replace the demo responses with genuine model outputs before making such claims.

## Setup

Python 3.9+ recommended.

```bash
python -m venv .venv
```

Activate the environment:

**Windows**
```bash
.venv\Scripts\activate
```

**macOS / Linux**
```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Run the evaluation

From the project root:

```bash
python src/evaluate.py --input data/demo_responses.csv --output-dir reports
```

The script creates:

- `reports/evaluated_responses.csv` — row-level metrics
- `reports/model_summary.csv` — model-level averages
- `reports/low_scoring_responses.csv` — responses to inspect
- `reports/model_comparison.png` — comparison chart

## Input CSV format

The input file must contain:

| Column | Meaning |
|---|---|
| `question_id` | Unique ID for the test question |
| `language` | Language label |
| `question` | Prompt or question |
| `reference_answer` | Human-written reference answer |
| `model_name` | Name/label of the model or system |
| `model_response` | Response being evaluated |
| `human_rating` | Optional human rating from 1 to 5 |

To evaluate real model outputs, replace the illustrative responses in the CSV with genuine outputs. Keep the same question set and reference answers for every model to make comparisons fair.

## Metrics and limitations

1. **Exact match:** 1 when the normalised response exactly matches the reference, otherwise 0. This is strict and can penalise valid paraphrases.
2. **Token precision, recall and F1:** Measures word-token overlap with the reference. It does not understand meaning and can miss valid synonyms.
3. **TF-IDF cosine similarity:** Measures lexical similarity using TF-IDF vectors. It is not a factuality or semantic-understanding metric.
4. **Human rating:** Optional 1–5 score. It is only meaningful when a human actually reviews and rates the response using a consistent rubric.

These metrics are proxies. They do **not** prove factual correctness, detect every hallucination, or replace expert human review. A stronger follow-up version could add model-based judging, API inference, blinded human annotation, inter-rater agreement, confidence intervals and multilingual evaluation.

## Suggested human review rubric

Rate each response from 1 to 5:

- **Correctness:** Is the answer factually consistent with the reference and reliable sources?
- **Relevance:** Does it answer the question asked?
- **Completeness:** Does it include the important information?
- **Clarity:** Is it understandable and well organised?

Record the overall rating in `human_rating`. Keep notes on why a response received its score.

## Reproducibility

- Keep the same questions and reference answers when comparing systems.
- Record the model name, model version, date, prompt template and inference settings when you add real model outputs.
- Do not compare results from different datasets as if they were directly comparable.
- Inspect low-scoring examples instead of relying only on average scores.
